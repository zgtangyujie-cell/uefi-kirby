# 当前状态与下一步（2026-10-26 收尾）

## 一句话

**显示已打通**：自制 UEFI 在 TB321FU 真机上能正常出画面。
**卡在输入**：屏幕只显示 Mu-Silicium 抬头，音量键无响应，进不了菜单。

## 已验证可用配置

```ini
# kirby.dsc
USE_CUSTOM_DISPLAY_DRIVER = 0        # SimpleFbDxe，复用引导器帧缓冲
PcdFrameBufferWidth       = 1600     # 面板原生竖屏宽度
PcdFrameBufferHeight      = 2560     # 面板原生竖屏高度
PcdFrameBufferColorDepth  = 32

# Resources/Configs/kirby.toml
[uefi_fd]           base = 0xF3800000   size = 0x400000
[boot_image_kernel] append_dtb = false
```

> **关键教训**：`PcdFrameBufferWidth/Height` 必须等于面板**原生扫描方向**（`1600 × 2560`）。
> 填成横向 `2560 × 1600` 会让整屏斜切，表现为「乱码」。这与系统 UI 横竖屏无关。

## 已确认的事实

| 项 | 值 | 依据 |
|---|---|---|
| bootloader 代号 | `kirby` | `fastboot getvar product` |
| SoC | SM8650 / Pineapple（Qualcomm 平台名 **Lanai**） | 原厂 `uefi_a.img` 构建路径 |
| FD 加载基址 | `0xF3800000` | 社区可用固件 BootShim 偏移 8 |
| FD 尺寸 | `0x400000`（4 MiB） | 同上 + 我们的构建 |
| gzip 载荷 | BootShim 112 B + FV 4 MiB = 4,194,416 B | 两份镜像一致 |
| 屏幕 | 面板原生 1600×2560 纵向 | dumpsys + dtbo |
| 面板 | NT36523 CSOT / BOE / BOE-hyper，DSC，120 Hz | dtbo `qcom,mdss_dsi_kirby_*` |
| 触摸 | NT36523N @ GENI SPI `0xA90000` | dtbo |
| userdata | `3613096` – `123365370`（4 KiB 扇区） | GPT + fastboot |

## 已修的两个真 bug

1. **FD 基址** `0xA7100000`（一加平板 Pro 的值）→ `0xF3800000`。修前直接关机，修后能进显示阶段。
2. **帧缓冲尺寸** `3000×2120`（一加）→ `1600×2560`（竖屏原生）。修前满屏乱码。

## 当前唯一阻塞：输入链路

```
ButtonsDxe ──提供──> SimpleInEx 协议 ──注册 SCAN_UP──> BootManagerLib.KeyCallback
                                                              │
                                                              ▼
                                               EnterBootManager()==TRUE 才进菜单
```

- 注册的键是 `SCAN_UP`（`KeyCallback.c:85`）
- 只有该标志为真才启动 Boot Manager Menu（`BootManager.c:156`）
- 屏幕上那行是 `PlatformBootManagerWaitCallback` 画的倒计时提示
- **无按键 → 永不进菜单 → 倒计时完 → 找不到启动项 → 关机**

### 为什么按键不通

`ButtonsDxe`（一加平板 Pro 的预编译版本）必须解析 DT 的
`/soc/buttons/buttons-config` 与 `/soc/buttons/platform-key-maps`。

这两个节点在**所有可得的 DT 里都不存在**：我们的 Linux DTB、11 份厂商 `vendor_boot` DTB、
全部 72 个 dtbo、原厂 `uefi_a.img` / `uefi.elf`。原厂那份是引导器运行时传进去的，磁盘上没有。
Mu-Silicium 官方的 163 份 `Resources/DTBs/*.dts` 同样是 Linux 风格，也没有。

## 按键：已找到官方 Schema，但两种投递方式都没生效

### 官方写法（已确认，来自 Qualcomm boot_images）

```dts
soc {
    buttons {
        buttons-config {
            compatible = "qcom,pm-button";
            /* BTNType GpioType PmicIndex GpioNumber Pulls Voltage OutBuf Source */
            gpio-configs = <0x00 0x01 0x01 0x06 0x00 0x01 0x00 0x00>;
        };
        platform-key-maps {
            compatible = "qcom,pm-keymap";
            /* PWR VOL_UP VOL_DOWN RESERVED RESERVED */
            key-maps = <0x01 0x02 0x03 0x00 0x00>;
        };
    };
};
```

宏值取自 `Settings/Include/button_defines.h`：
`VOL_UP_BTN=0`、`PMIC_GPIO=1`、`PULL_UP_30uA=0`、`VIN1=1`、`DRV_STR_LOW=0`、`SRC_GND=0`、
`PWR=1`、`VOL_UP=2`、`VOL_DOWN=3`、`RESERVED=0`。
我们的 DTB 显示音量键在 **PMIC GPIO 6**，与参考平台一致。

### 已试过、都不行

| 方式 | 结果 |
|---|---|
| `append_dtb = false`（无设备树） | 出抬头，无菜单 |
| `append_dtb = true` + 上面的最小 DTS | 出抬头，无菜单 |
| FdfBlob 内嵌（`25462CDA` + `DtPlatformDxe`） | **卡死 logo**，比原来更糟，已回退 |

说明：追加的 DT 可能没有送到 `ButtonsDxe` 手里（固件可能从 PCD 指定的地址取 DT，
而不是 boot.img 尾部），或者 `gpio-configs` 里的 `PmicIndex`/`GpioNumber` 取值不对。
