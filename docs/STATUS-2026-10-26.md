# 当前状态与下一步（2026-10-26 收尾）

## 一句话

固件能编、能启动、能往屏幕写字，但**画面是乱码**，还没看到 BDS 菜单。

## 已经确认的事实（都有实测依据）

| 项 | 值 | 依据 |
|---|---|---|
| bootloader 代号 | `kirby` | `fastboot getvar product` |
| SoC | SM8650 / Pineapple（Qualcomm 平台名 **Lanai**） | 原厂 `uefi_a.img` 构建路径 |
| FD 加载基址 | **`0xF3800000`** | 社区可用固件的 BootShim 偏移 8 |
| FD 尺寸 | `0x400000`（4 MiB） | 同上 + 我们的构建 |
| gzip 载荷 | BootShim 112 B + FV 4 MiB = 4,194,416 B | 两份镜像一致 |
| 追加 DTB | **无**（社区同样无） | 社区 boot.img 尾部 0 字节 |
| 屏幕 | 2560×1600（面板原生 1600×2560 纵向） | dumpsys + dtbo |
| 面板 | NT36523 CSOT / BOE / BOE-hyper，DSC，120 Hz | dtbo `qcom,mdss_dsi_kirby_*` |
| 触摸 | NT36523N @ GENI SPI `0xA90000` | dtbo |
| userdata | `3613096` – `123365370`（4 KiB 扇区） | GPT + fastboot |

## 已修的两个真 bug

1. **FD 基址**：`0xA7100000`（一加平板的）→ `0xF3800000`。修之前设备直接关机，修之后能跑到显示阶段。
2. **帧缓冲尺寸**：`3000×2120`（一加）→ `2560×1600`。

## 当前症状

- `fastboot boot` 正常接受镜像，设备进入固件，不写分区
- 屏幕出现文字，但**乱码**（不是纯黑，也不是花屏噪点）
- 之后无响应，需长按电源回 Android

## 已经排除的方向

| 假设 | 结论 |
|---|---|
| `fastboot boot` 不支持自定义 UEFI | ❌ 排除：社区固件能出画面 |
| 内存表写错 | 大概率排除：33 条 DDR 项零重叠，37 个保留区零冲突 |
| 缺 `uefiplat.cfg` | ❌ 排除：`RAW.inc` 里一直有，且预检 68 个引用 0 缺失 |
| 缺厂商显示驱动 | ❌ 排除：`USE_CUSTOM_DISPLAY_DRIVER=1` 已开，61 个面板 XML（含 3 份 kirby）在卷内 |
| 缺 TZ/SCM 驱动 | 部分排除：我们有 `TzDxe`/`ShmBridgeDxe`（老命名），只是没有 `_LA` 变体 |

## 下一步，按性价比排序

### 1. 换成 `SimpleFbDxe` 并用正确 PCD 尺寸（最省事，先做）

`USE_CUSTOM_DISPLAY_DRIVER = 0` + `PcdFrameBufferWidth/Height = 2560/1600`。

意义：完全绕开厂商 `DisplayDxe`，用最朴素的「复用引导器帧缓冲」路径。如果这样能出正常文字，说明乱码是厂商驱动与我们的 PCD 冲突；如果连文字都没有，说明帧缓冲根本没建立。

### 2. 让日志不再依赖屏幕（真正解决问题）

把 UEFI 日志写进 `ramoops` 保留区（`0xA2000000`，4 MiB，DTB 里标了 `no-map`），
固件崩溃或重启后 Android 的 `/sys/fs/pstore/` 会保留内容：

```bash
adb shell ls /sys/fs/pstore/
adb shell cat /sys/fs/pstore/dmesg-ramoops-0
```

这样以后定位问题**完全不用看屏幕**。需要我们在 DXE 里加一个日志写的驱动，
或利用 Mu 自带的 `ULogDxe`（需确认它是否支持 ramoops 后端）。

### 3. 换基座到 Project-Aloha（大工程，但不是现在）

社区固件来自 `mu_aloha_platforms_y700_standardized`（guf296 本地定制，**未公开**）。
上游 `Project-Aloha/mu_aloha_platforms` 只有 SDM845 / SM8550 / SM7150 / SM8750 平台，
**没有 SM8650**。所以这条路要么等作者开源，要么我们自己往 Aloha 里加一个 Pineapple 平台（工作量以天计）。
